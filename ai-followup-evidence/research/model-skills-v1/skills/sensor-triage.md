# Read the sensor record

1. Treat supplied counts, actions, signatures and coverage as fixed facts.
2. Review blocked and severity-1 evidence before ordinary repetitions.
3. Select only a permitted interpretation for the exact group it describes.
4. Keep record count distinct from packet, request, session and connection count.
5. Treat STUN as possible NAT traversal; it does not identify the responsible process or establish benign intent.
6. A signature match alone does not establish an intrusion. A UID fixture explanation needs a matching owned test receipt.

Example: 15 allowed STUN alert records with no process or client receipt support possible NAT traversal, unknown process and unknown client result. They do not support "15 successful connections."
