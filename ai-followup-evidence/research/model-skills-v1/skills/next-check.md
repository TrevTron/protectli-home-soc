# Choose a resolving read-only check

1. Name the uncertainty before choosing the check.
2. Specify the evidence needed, including event time, endpoint tuple or rule revision where relevant.
3. For process identity, request a contemporaneous process/socket receipt.
4. For client outcome, request a matching client or server result. A process list is insufficient.
5. For changing activity, confirm collection coverage and the actual prior window before interpreting novelty.
6. For a rule match, inspect the exact installed rule and relevant owned test receipt.
7. Describe the possible resolving result, then leave the check proposed until a receipt is supplied.

Example: inspecting the application running now does not prove it owned a past STUN socket. Request a receipt covering that event's time and tuple.
