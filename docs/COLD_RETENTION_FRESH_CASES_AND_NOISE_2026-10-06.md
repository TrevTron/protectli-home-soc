## Keeping exact evidence available

`soc_cold_evidence.py` verifies bounded checkpoint archives, creates a catalogue and reads the source's original global byte offset and length. It verifies the full original record SHA256 before returning bytes. A catalogue entry is checked against the archive's full hash, member hashes, logical layout and existing restoration checks. Changed or incomplete evidence is withheld. It does not treat the short displayed evidence ID as the full digest.

The copy-only rehearsal verified 868 archive members, 4,820 references, 123 saved report bundles and two historical operator notes against a 160,575,047-byte original prefix. Two early report references reopened through the new resolver matched the current original bytes exactly. The source checkpoint's SHA256 stayed `7446dde81994938b7fec5aea64bd6e7f9cc2116c6e65046c0509a7c289863231`. The original corrected-study ZIP and five existing core modules also retained their baseline hashes.

Pins store explicit context and exact cited record bytes. A separate saved receipt binds the case manifest, so verification can detect later context edits as well as changed records. An archived note copied as context does not establish that it belongs to the early report; these inputs are preserved as distinct historical material, not a new investigation conclusion. Locally rewritten evidence and rewritten receipts remain an administrator trust limitation.

The seven-day preview retains the active segment, recent or future-dated records, unknown ages, missing archive coverage and segments intersecting unresolved pins. An old sealed segment becomes eligible only after its complete bytes match a verified archived member. Testing uses disposable copies. The real preview returned zero eligible bytes because the records are recent. No deletion or movement is implemented or enabled.

This does not yet solve indefinite live retention. The current aggregate raw limit remains 1 GiB and collection still stops retaining new records at that limit. Existing live readers require the complete hot layout. SQLite, report reads, source routes, receiver startup, capacity reporting and archive scheduling need a coordinated migration before any hot segment can be reclaimed. The separate archive budget also needs a retention decision. Seven days of time retention cannot override a byte limit silently; show the conflict and preserve pinned cases.

## Narrow noise labels

`soc_noise_policy.py` implements expected-context labels, rather than hiding rows. Its first supported scope binds SID, installed rule revision, client, destination, protocol, destination port, allowed action and severity three. Source ports remain outside policy scope because they can be ephemeral. The future adapter must combine counts over that scope rather than treating separate source ports as independent allowances.

A policy records its own revision, reason, supporting case hash, a count/window bound and expiry within seven days. Preview preserves counts, references, visibility and existing priority floors. A block or severity-one record is always review-first. Changed endpoints, rule revisions, destination ports, protocols, actions or severities stay under review. Missing verified sources/comparison/scope, malformed references, bursts and changed windows prevent an expected label. Duplicate scope rows are refused to prevent splitting a burst beneath the threshold.

Offline activation requires the exact reviewed preview hash, supporting case receipt, matching policy and a preview no older than one hour. Rollback is bound to the current state hash and preserves the previous revision. This is a prepared state transition, not an installed live workflow or proof that a human reviewed a case. The model cannot create or activate policies. The module has no Vault API, network listener, evidence deletion or live-service import. TriageWall remains related design context; these functions were implemented here without copying its code.
