# Ling revision and matched transfer protocol

The target is the private, synthetic local analyst workbench. The historical 0/12 Ling result stays intact. No production dashboard, active analyst tools, old result files or model-store artifacts are edited.

Development tests use D03, D04, D08 and D12: exact matching success and failure receipts, empty incomplete coverage and unavailable prior-window coverage. Four initial profiles separate inherited versus consistent prompt, non-thinking versus greedy reasoning, and greedy versus publisher sampling. All use seed 17, context 8,192 and overall completion ceiling 4,096. The initial reasoning cap is 1,024 tokens.

The initial reasoning traces reached that cap on all eight enabled-thinking requests. A separately sealed extension tests the same evidence and two reasoning/sampling profiles with a 3,072-token reasoning cap. The overall completion ceiling and finite 300-second request deadline stay the same. This is an additional development contrast, not a retry, answer repair, new evaluation case or change to the original score. The original initial-profile selection file is preserved; extended selection receives its own file.

Select the greatest number of strict six-dimension development passes. Resolve ties in this predeclared order: clean-off, clean-think, clean-native, clean-think-long, clean-native-long. The inherited prompt control cannot be promoted. Record actual returned reasoning, final JSON, native generation prefix, source/input hashes and observed forced reasoning closure.

After freezing that choice, construct N01 to N12 from the twelve known scenario families. Vary timestamps, attempt identifiers, flow tuples, counts, record and receipt order. Add three near-match client receipts to each nonempty case, differing in event time, attempt ID or destination port. The retry's earlier blocked records are distinct from its later allowed attempt. Include two empty cases with different retained/prior coverage. Private expected outcomes are derived from complete original records and receipts. No private family labels, oracles or code-classified receipt matches reach a model.

The common lane sends each new case to Gemma 4 12B IT QAT, Qwen 3.5 4B, Qwen 3 4B Instruct 2507, Qwen 3.5 9B and Ling 3.0 tiny. All receive the same revised skill, raw evidence and six-field schema, with greedy sampling and thinking disabled. If the selected Ling profile differs, execute one additional Ling lane on the exact same cases with only its declared reasoning/sampling profile different. All final requests are frozen before inference. One draw per case/profile, no retries or repairs.

Primary quality measure: all six decision dimensions correct on a case. Secondary measures: separate context, check, client outcome, client reference and two boundary-claim totals. A valid, complete JSON response is a delivery measure, not a semantic pass. Both boundary dimensions test unjustified positive claims; these fixtures do not demonstrate positive intrusion detection or prove UDP delivery.

The runs use the existing owned CPU endpoint and a temporary authenticated, loopback-only native Ling CPU child. Inference is sequential. Existing maintenance ownership, collector separation, native health monitoring, finite load/request deadlines and 16 GiB spare-memory floor remain. Restore the ordinary Qwen reporter and verify a fresh completed report and current socket ownership after the batches. No new host thermal certification is claimed.

New cases are author-known, synthetic variants of development families. Changing receipt distractors increases matching difficulty, while shorter source windows can reduce prompt length. New scores therefore describe the new matched test; they are not a controlled before/after comparison with the older F pack. Parameter counts, quantization and runtimes differ. A highest observed score is a test leader, not a population, throughput or model-family ranking. The publisher-sampling lane has only one stochastic seed.
